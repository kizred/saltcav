# План разработки ПО

ПО строится как Python-пакет из независимых модулей с общими структурами данных; каждый
этап заканчивается рабочей версией с тестами, а не набором заготовок. Галочки отмечают
сделанное; подробности и даты — в [`progress.md`](progress.md).

Следующая версия — [`roadmap-2.0.md`](roadmap-2.0.md): произвольная 3D-геометрия камер
и скважин; этапы 10–16 и промежуточные выпуски 1.2–1.5.

## Принципы и стек

**Принципы**

- Физическое ядро отделено от стохастики, ввода-вывода и визуализации: модель
  выщелачивания — чистая функция «параметры + режим → история формы».
- Каждая реализация Монте-Карло полностью определяется конфигурацией и seed, поэтому любой
  результат воспроизводим.
- Единицы СИ внутри кода, перевод только на вводе и выводе.
- Сначала простое и проверенное (осесимметрия), затем расширение; каждая новая возможность
  приходит вместе с тестом.
- Медленные части (геомеханика) изолированы и заменяемы суррогатом.

| Задача | Инструмент |
| --- | --- |
| Язык и окружение | Python 3.11–3.13, venv/uv или conda (FEniCSx удобнее ставить через conda) |
| Численное ядро | NumPy, SciPy, Numba |
| Случайные поля и чувствительность | gstools, SALib, scipy.stats.qmc |
| Параллельные прогоны | joblib локально, Dask или Ray на кластере |
| Сетки и МКЭ | Gmsh (Python API), FEniCSx (dolfinx) |
| Суррогаты | scikit-learn, GPyTorch или PyTorch |
| Байесовская калибровка | PyMC или emcee |
| Конфигурации | YAML + pydantic для проверки |
| Хранение результатов | NetCDF/xarray или Zarr (пока .npz) |
| Качество кода | git, pytest, ruff, mypy, pre-commit |
| CI | GitHub Actions |
| Документация | MkDocs + mkdocstrings, Jupyter-примеры |
| Визуализация | Matplotlib, PyVista, ParaView |

## Структура репозитория

Один репозиторий, один пакет `saltcav` с подпакетами по модулям паспорта; тяжёлые
зависимости (FEniCSx, PyTorch) — опциональные.

```
saltcav/
├── pyproject.toml
├── configs/                 # YAML: геология, режим, сетки, ансамбли
├── data/                    # исходные данные (под DVC, не в git)
├── src/saltcav/
│   ├── core/                # единицы, конфигурация, свойства рассола, генераторы
│   ├── geometry/            # R(z, φ), объём, площади, нормали, углы ψ
│   ├── leaching/            # стратификация, струя, растворение, нерастворимые, карнизы
│   ├── operations/          # график режима: расход, колонны, нерастворитель
│   ├── stochastic/          # случайные поля, прослои, сэмплеры, ансамбли
│   ├── mesh/                # R(z, φ) → Gmsh
│   ├── mechanics/           # FEniCSx: ползучесть, критерии
│   ├── surrogate/           # признаки формы, обучение, предсказание
│   ├── calibration/         # невязки с данными, байесовское обновление
│   ├── io/                  # чтение данных компании, сонара, запись результатов
│   ├── viz/                 # профили, 3D, карты вероятностей
│   └── cli.py               # запуск: check, run, ensemble, mechanics, calibrate
├── tests/
│   ├── unit/
│   ├── verification/        # аналитика, баланс массы, бенчмарки
│   └── regression/          # эталонные результаты
├── benchmarks/              # SANSMIC, опубликованные профили
├── notebooks/               # примеры и анализ
└── docs/                    # паспорт, план ПО, прогресс, журнал решений
```

## Модель данных и интерфейсы модулей

Модули обмениваются только неизменяемыми структурами данных; это позволяет тестировать
каждый модуль отдельно и заменять реализации (например, МКЭ на суррогат).

| Структура | Содержание | Статус |
| --- | --- | --- |
| `RunConfig` | Проверенная YAML-конфигурация прогона | есть |
| `CavernGrid` | Узлы z (м), число секторов φ, шаги | есть |
| `Cavern` | Форма R(z, φ) в момент времени: объёмы, площади, углы ψ, нормали | есть |
| `Schedule`, `Stage` | Ступени режима в СИ с индексами слоёв башмаков и нерастворителя | есть |
| `History` | Моменты прогона: R, C(z), объём, растворённая и вынесенная соль | есть |
| `Geology` | Поля f_ins(z, φ), множитель k(z, φ), прослои | этап 4–5 |
| `EnsembleResult` | Набор `History` + seed и параметры каждой реализации, квантили | этап 5 |
| `StabilityResult` | Запас устойчивости, конвергенция, нарушенные критерии | этап 6 |

**Ключевые функции**

```python
simulate(cfg: RunConfig) -> History                       # есть
sample_geology(prior: GeologyPrior, rng: Generator) -> Geology
run_ensemble(cfg: RunConfig, n: int, seed: int) -> EnsembleResult
build_mesh(cavern: Cavern, domain: Domain) -> Mesh
assess_stability(mesh: Mesh, material: SaltMaterial, loads: Loads) -> StabilityResult
shape_features(cavern: Cavern) -> np.ndarray
posterior(prior, data: FieldData, model) -> Samples
```

Любая функция с данными компании на входе сначала проходит валидацию pydantic: единицы,
диапазоны, пропуски.

## Этапы разработки

Десять этапов, ориентировочно 27–39 недель для одного разработчика; этапы 6 и 8 можно вести
параллельно с 3–5, если работают двое. Оценки — прикидка, уточняются после этапа 2.

| Этап | Модули | Оценка, нед. | Фаза дорожной карты | Статус |

| 0. Инфраструктура | репозиторий, CI | 1 | 1 | готово |
| 1. Ядро и геометрия | core, geometry | 1–2 | 1 | готово |
| 2. Выщелачивание, осесимметрия | leaching, operations | 4–6 | 2 | готово (ворота Г2) |
| 3. 3D по азимуту | leaching, geometry | 2–3 | 2 | готово |
| 4. Прослои и карнизы | leaching | 2–3 | 2 | готово |
| 5. Стохастика и ансамбли | stochastic | 3–4 | 3 | готово |
| 6. Сетка и геомеханика | mesh, mechanics | 6–8 | 3 | готово (сверка с коммерческим пакетом — открыта) |
| 7. Суррогат | surrogate | 2–3 | 3 | готово |

## Тестирование и верификация

Верификация («уравнения решены правильно») встроена в CI; валидация («уравнения
правильные») идёт отдельно на данных.

| Уровень | Что проверяет | Примеры | Когда запускается |
| --- | --- | --- | --- |
| Модульные | Отдельные функции | Свойства рассола, объём R(z, φ), углы ψ | Каждый коммит |
| Инварианты | Законы, которые нельзя нарушить | Сохранение массы соли, R не убывает, осесимметрия при однородных свойствах, воспроизводимость по seed | Каждый коммит |
| Сходимость | Порядок точности | Измельчение сетки и шага по времени, MMS для МКЭ | Ночной прогон |
| Аналитика | Совпадение с точными решениями | Рост цилиндра и сферы; полость в упругой и ползучей среде | Каждый коммит / ночной |
| Бенчмарки | Совпадение с другими кодами | SANSMIC, коммерческий МКЭ | Перед релизом этапа |
| Регрессия | Отсутствие незапланированных изменений | Эталонные ансамбли малого размера | Каждый merge |
| Валидация | Соответствие реальности | Физическая модель, данные компании, сонар | По мере поступления данных |

Целевое покрытие тестами ядра (core, geometry, leaching, stochastic) — не ниже 80 %.

## Производительность и вычисления

Бюджет времени задаётся ансамблем: тысячи прогонов выщелачивания и сотни расчётов МКЭ.

| Расчёт | Цель по времени | Сейчас | Средство |
| --- | --- | --- | --- |
| Одна камера, осесимметрия | ≤ 1 с | 0,3 с с плюмом (240 сут, 200 слоёв) | NumPy; Numba при необходимости |
| Одна камера, 3D по φ | ≤ 10 с | 0,6 с (36 секторов) | NumPy |
| Ансамбль 1000 реализаций | ≤ 1 ч на рабочей станции | 4,2 мин на 2 ядрах (12 секторов) | процессы по ядрам, число — по свободной памяти, BLAS однопоточный |
| Один расчёт МКЭ с ползучестью | минуты – десятки минут | осесимметрия 15 лет — 7 с; 3D с прослоем — ≈ 1 мин | свой МКЭ: SuperLU (2D), PARDISO + PCG (3D), повторное использование разложения |
| Суррогат, одно предсказание | ≤ 10 мс | < 1 мс | гауссов процесс в памяти (scikit-learn) |

- Реализации ансамбля независимы, поэтому масштабируются почти линейно по числу ядер.

## Данные, конфигурации и воспроизводимость

Любой результат в отчёте должен восстанавливаться из трёх вещей: версии кода,
конфигурации и версии данных.

- **Данные компании** хранятся вне git (`data/` в `.gitignore`), версионируются через DVC;
  доступ ограничен, если данные конфиденциальны.
- **Конфигурации** YAML с проверкой pydantic: геология, режим, сетка, растворение,
  ансамбль. Конфигурация каждого прогона сохраняется рядом с результатом.
- **Seed** фиксируется для ансамбля; seed каждой реализации выводится из него
  детерминированно (`numpy.random.SeedSequence`).
- **Результаты** пишутся с метаданными: хеш коммита, версия данных, дата, конфигурация.
- **Учёт экспериментов**: MLflow или простой журнал прогонов — для сравнения калибровок и
  суррогатов.
- **Окружение** фиксируется lock-файлом; для расчётов на кластере — контейнер (Docker или
  Apptainer).

## Визуализация и отчётность

Визуализация отделена от расчёта: она читает только сохранённые результаты.

- Профили R(z) по выбранным азимутам с огибающими P10/P50/P90 и сонаром поверх (если есть).
- Горизонтальные сечения камеры на заданных глубинах.
- 3D-вид камеры (PyVista), экспорт в ParaView; поля напряжений и конвергенции из МКЭ.
- Карты вероятностей: превышение радиуса, выход кровли, нарушение целика.
- Графики сходимости ансамбля и индексы чувствительности Соболя.
- Сравнение расчёта с данными компании: растворённый объём и выходная концентрация во
  времени.
- Команда `saltcav report` собирает всё в HTML или PDF по шаблону.

## Риски разработки

| Риск | Признак | Ответ |
| --- | --- | --- |
| Явная схема неустойчива на нависающих участках | Осцилляции R, отрицательные шаги | Схема Годунова, ограничение шага (КФЛ); при необходимости level-set |
| Ансамбль не укладывается во время | 1000 реализаций > 1 ч | Профилирование, Numba, кластер, квази-Монте-Карло вместо чистого |
| Сложность установки FEniCSx | Окружение не собирается у пользователей | conda-окружение, контейнер; механика как опциональная часть |
| Генерация сетки падает на сложных формах | Ошибки Gmsh на карнизах | Упрощение поверхности перед сеткой, автоматическая проверка, откат на сглаженную форму |
| Нелинейная ползучесть не сходится | Расходимость Ньютона | Адаптивный шаг по времени, начальное упругое решение, проверка на простой геометрии |
| Данные компании приходят поздно или неполными | Этап 8 простаивает | Синтетические данные для отладки калибровки, интерфейс загрузчика фиксируется заранее |
| Разрастание кода без тестов | Регрессии после изменений | Правило: без теста изменение не принимается; регрессионный набор в CI |
