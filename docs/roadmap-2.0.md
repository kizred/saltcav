# План версии 2.0

Версия 1.x моделирует одну камеру вокруг одной вертикальной скважины: форма — радиус
R(z, φ) от оси. Это быстро и проверено (SANSMIC, аналитика), но не описывает наклонные
и кривые стволы, струю под углом, несколько скважин и камер, слияние полостей и старые
выработки в массиве. Версия 2.0 снимает это ограничение: **произвольная трёхмерная
геометрия камер и скважин** и всё остальное — ансамбли, калибровка, геомеханика,
суррогат, отчёт — поверх неё.

Документ — в том же порядке, что и [`software-plan.md`](software-plan.md): цели,
принципы, этапы с задачами и приёмкой, ворота, риски. Галочки отмечают сделанное; ход
работ — в [`progress.md`](progress.md), решения — в [`decisions.md`](decisions.md).

## Принципы

- **Модель 1.x остаётся.** Осесимметричная и азимутальная модель — быстрый режим и
  эталон: на камере вокруг вертикальной скважины новое ядро обязано давать тот же
  результат (ворота Г5). Старые конфигурации открываются без изменений.
- **Сначала решение о представлении геометрии — на прототипе**, потом основная работа.
- **Компилируемое ядро.** Горячие циклы нового ядра (шаги по сетке) — сразу на Numba;
  если её не хватит — Rust (PyO3) или C++ (pybind11). Оболочка — Python, как сейчас.
- **Каждый этап — рабочий выпуск** (1.2, 1.3 … 2.0-alpha, 2.0-beta), с тестами и
  установщиком; ничего не ломаем в уже выпущенном.
- **Без CFD.** Струя и перемешивание — инженерные модели, откалиброванные по данным;
  полная гидродинамика сделала бы ансамбли невозможными.
- **Каждая цифра в библиотеке материалов — с источником.** Без источника значение не
  попадает в библиотеку.

## Ключевое решение: как описывать стенку

Решается на этапе 10 по прототипу; ниже — исходная оценка.

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| Несколько R(z, φ) от разных осей | почти без нового кода | не описывает наклон, слияние, нависания по-настоящему |
| Поверхностная сетка (треугольники), движение узлов | точная поверхность, легко в Gmsh | слияние и самопересечения — тяжёлая отдельная задача |
| **Неявная функция (level set) на объёмной сетке** | слияние, ниши, нависания — автоматически; скорость растворения = скорость по нормали; поверхность для МКЭ — marching cubes | память и время; точность ~ шаг сетки; нужны узкая полоса и Numba |

Предпочтение — **level set в узкой полосе** на прямоугольной сетке с шагом 0,25–1 м.
Рассол остаётся слоистым по глубине (как в 1.x), но отдельно для каждой связной
полости — горизонтальное перемешивание внутри полости быстрое; это допущение
проверяется на этапе 11.

### 1.x-а. Библиотека материалов и рабочих сред (1.2)

- [ ] Формат библиотеки: YAML-файлы `materials/` (породы) и `fluids/` (рабочие среды),
  у каждого значения — единицы, диапазон и источник
- [ ] Породы: каменная соль (несколько месторождений и наборов ползучести BGRa,
  Мансон–Доусон), ангидрит, глина, сильвинит и карналлит, известняк, доломит —
  упругость, прочность, ползучесть, растворимость
- [ ] Рабочие среды: вода, рассолы NaCl (плотность, вязкость, насыщение по T),
  нерастворители — дизтопливо, нефть, азот, воздух (плотность, сжимаемость)
- [ ] Вязкость рассола (открытый пункт этапа 1) — из библиотеки
- [ ] Слой в конфигурации ссылается на материал по имени; можно переопределить любое
  свойство; разброс для ансамбля — тоже из библиотеки
- [ ] В окне: выбор материала из списка, карточка свойств с источниками; свои материалы —
  в папке пользователя

**Приёмка:** все значения по умолчанию из 1.x воспроизводятся через библиотеку (те же
результаты); у каждой записи есть источник; проверка схемы ловит несогласованные единицы.

### 1.x-б. Настраиваемая сетка и решатели МКЭ (1.3)

- [ ] Параметры сетки в конфигурации и в окне: размер у стенки, у кромок, у прослоев,
  рост, порядок элементов, внешние границы; предпросмотр сетки до расчёта
- [ ] Выбор решателя (SuperLU, PARDISO, PCG, повторное разложение) и допусков; авто — по
  размеру задачи, как сейчас
- [ ] Интерфейс закона ползучести: свой закон — Python-класс с проверкой на тестовой
  задаче (цилиндр, аналитика); встроенные — BGRa, Мансон–Доусон, Norton, степенной с
  двумя механизмами
- [ ] Интерфейс решателя: подключаемый модуль с тем же контрактом (матрица → решение) и
  автоматической сверкой со встроенным
- [ ] Контакт соль–прослой с проскальзыванием (открытый пункт этапа 6) — по желанию

**Приёмка:** любая комбинация настроек проходит аналитические тесты этапа 6; свой закон
ползучести подключается без правки кода пакета.

### 1.x-в. Суррогат: улучшение обучения (1.4)

- [ ] Метрика «лучше»: число полных МКЭ при заданной ошибке вероятности; эталон —
  полный расчёт на всём ансамбле (небольшая задача)
- [ ] Активное обучение по ожидаемому влиянию на вероятность (а не только по знаку
  запаса), пакетный отбор под параллельный счёт
- [ ] Многоуровневая схема: дешёвая модель (грубая сетка, осесимметрия) + поправка по
  полным расчётам (co-kriging)
- [ ] Отбор признаков формы, проверка переноса между режимами
- [ ] Индексы Соболя по суррогату (открытый пункт этапа 5)

**Приёмка:** при той же ошибке вероятности — не меньше чем вдвое меньше полных расчётов
МКЭ на тестовом наборе.

### 1.x-г. Открытые пункты 1.x и интерфейс (1.5)

- [ ] Механика при меняющейся форме: ползучесть во время выщелачивания (открытый

- [ ] Смещение струи от оси (открытый пункт этапа 3) — частный случай этапа 12, здесь —

- [ ] Независимая сверка 3D-геомеханики (SafeInCave или коммерческий пакет) — при

**Приёмка:** ползучесть при меняющейся форме совпадает с нынешним расчётом при

### 10. Прототип геометрии 3D (2.0-dev)

- [ ] Прототип level set в узкой полосе: перенос по нормали, реинициализация, объём и
  площадь, извлечение поверхности
- [ ] Тот же рост, что у модели 1.x, на цилиндре, конусе, камере с карнизом
- [ ] Замеры: память и время на камеру 100 × 60 × 60 м при шаге 0,25, 0,5 и 1 м; Numba

- [ ] Решение о представлении — в `decisions.md`

**Ворота Г5а:** точность формы ≤ 1 шага сетки против аналитики и модели 1.x; одна камера
на 240 сут — ≤ 30 с на рабочем шаге. Если нет — пересмотр варианта.

### 11. Ядро выщелачивания 3D (2.0-alpha1)

- [ ] Геометрия: `Domain` (сетка массива), `Cavity` (связная полость), объём и площадь
  по глубине, нормали, угол ψ на поверхности
- [ ] Растворение: j = k0·f(ψ)·C_s·u^n по нормали — те же законы, что в 1.x
- [ ] Рассол: слоистый баланс по глубине для каждой связной полости, слияние полостей —
  объединение балансов
- [ ] Нерастворимые: высвобождение, осаждение, подъём подошвы по реальной форме дна
- [ ] Прослои — непроницаемые слои любой ориентации (наклон пласта), карнизы и
  обрушение по пролёту
- [ ] Нерастворитель — горизонтальная граница по графику
- [ ] Сохранение, просмотр (`saltcav view`) и экспорт VTK для новой формы

**Ворота Г5:** на вертикальной скважине результат совпадает с моделью 1.x (объём ±1 %,
R(z, φ) ± шаг сетки), баланс соли < 1 %, сходимость при измельчении; сверка с SANSMIC
сохраняется.

### 12. Скважины в xyz и направленные струи (2.0-alpha2)

- [ ] Ствол по инклинометрии (глубина по стволу, зенит, азимут) или по точкам xyz;
  кривизна, обсадка, башмаки колонн в xyz
- [ ] Несколько скважин и колонн в одной камере и в массиве; режим — по каждой колонне
- [ ] Струя: направление (ось колонны или задаваемое), угол раскрытия, расход и скорость
  на выходе; наклонная и горизонтальная струя, прилипание к стенке (эффект Коанды) —
  инженерная модель
- [ ] Поле скорости у стенки от струй → u в законе растворения
- [ ] Проверка: вертикальная струя = плюм 1.x; литература по наклонным струям в
  стратифицированной среде; данные физической модели, если будут

**Приёмка:** вертикальный случай совпадает с 1.x; наклонный ствол даёт ожидаемую
асимметрию; параметры модели струи — с источниками и диапазонами для ансамбля.

### 13. Массив: несколько камер и полостей (2.0-alpha3)

- [ ] Конфигурация массива: размеры, пласты (в том числе наклонные), существующие
  полости и выработки — из файла (STL, OBJ, облако сонара) или примитивами
- [ ] Несколько камер одновременно, каждая со своим режимом; слияние при встрече
- [ ] Целик между камерами: минимальная толщина во времени, предупреждение о сближении
- [ ] Импорт сонара 3D как исходной формы (продолжение расчёта от съёмки)

**Приёмка:** две камеры, растущие навстречу, сливаются с сохранением массы соли;
существующая полость из файла учитывается в росте и в балансе.

### 14. Геомеханика на 3D-геометрии (2.0-beta1)

- [ ] Сетка из новой формы: поверхность (marching cubes) → упрощение и сглаживание →

- [ ] Несколько камер и полостей в одной модели, целики; внешние границы по массиву

**Ворота Г6:** на вертикальной камере — совпадение с 3D-МКЭ 1.x (конвергенция ± 2 %,

### 15. Ансамбли, калибровка, суррогат на 3D (2.0-beta2)

## Риски

| Риск | Признак | Ответ |
| --- | --- | --- |
| Level set медленный или неточный | Г5а не пройдены | шаг и узкая полоса, Numba → Rust; запасной вариант — поверхностная сетка |
| Слоистый рассол в сложной полости неверен | расхождение с данными по концентрации | рассол по связным частям и уровням; при нужде — простая многозонная модель |
| Модель наклонной струи без данных не проверить | разброс литературы больше эффекта | широкий разброс в ансамбле, калибровка по сонару; запрос физической модели |
| Сетка МКЭ из неявной поверхности падает | ошибки Gmsh на тонких местах | сглаживание и упрощение поверхности, проверка качества, откат на более грубую форму |
| Ансамбль 3D не укладывается во время | > 10 ч на 1000 реализаций | грубая сетка + поправка, многоуровневый Монте-Карло, кластер |
| 2.0 ломает привычную работу | старые конфигурации дают другое | режим 1.x сохраняется, регрессионный набор 1.x в CI |
| Разрастание объёма | этапы затягиваются | этапы 1.x независимы и выпускаются отдельно; в 2.0 — только А–В обязательны |

## Вне 2.0 и на потом
