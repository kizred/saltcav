# Журнал решений

Формат: дата — решение — почему — альтернативы.

## 2026-10-24 — Свой код выщелачивания, готовая библиотека для геомеханики

- **Решение:** модель выщелачивания пишем сами (Python + Numba) на сетке R(z, φ);
  геомеханику считаем в FEniCSx, свой МКЭ не пишем.
- **Почему:** выщелачивание — научная новизна и должно быть быстрым для Монте-Карло;
  нелинейная ползучесть в 3D требует проверенного решателя и верификации.
- **Альтернативы:** свой МКЭ (долго, трудно верифицировать); MOOSE (выше порог входа);
  только коммерческие пакеты (нет контроля над моделью, используем для сверки).

## 2026-10-24 — Случайность во входных данных, а не в событиях растворения

- **Решение:** Монте-Карло по реализациям геологии и режима с коррелированными полями.
- **Почему:** при заданных условиях растворение почти детерминировано; независимые
  ячейки дают нефизичный шум.
- **Альтернативы:** вероятностный клеточный автомат с независимыми ячейками.

## 2026-10-24 — Источники данных для калибровки

- **Решение:** основа — данные компании; физическая модель для k(θ) и стратификации;
  сонар при возможности. До получения данных — открытые: SANSMIC, отчёты SPR, литература.
- **Почему:** данные компании описывают реальный объект; физмодель даёт контролируемые
  условия; открытые данные позволяют отладить код заранее.

## 2026-10-24 — Конфигурация: YAML + pydantic, единицы в именах полей

- **Решение:** строгая схема (лишние поля запрещены), единицы в имени поля
  (`rate_m3_per_h`), перевод в СИ через свойства.
- **Почему:** ошибки единиц и опечатки в конфигурации ловятся при загрузке, а не в
  середине ансамбля.

## 2026-10-24 — Геометрия: фрустумы по z, секторы по φ

- **Решение:** стенка R задаётся в узлах глубины (nz+1) и центрах nphi секторов; между
  узлами — усечённый конус. Радиальные грани между секторами в площадь растворения не входят.
- **Почему:** точно для цилиндра и конуса, второй порядок сходимости для гладких форм,
  дешёвые векторные вычисления; согласуется со слоями концентрации C(z).
- **Альтернативы:** ступенчатые цилиндры (первый порядок), level-set (дорого для ансамблей).

## 2026-10-24 — Угол ориентации стенки ψ

- **Решение:** ψ — угол между нормалью «в соль» и вертикалью вверх: 0° кровля,
  90° вертикаль, 180° подошва. Закон k(ψ) задаётся в этой системе.
- **Почему:** однозначно и не зависит от направления оси z. В литературе встречаются
  другие соглашения (например, 180° для растворения вверх) — при переносе коэффициентов
  из статей угол пересчитывать.

## 2026-10-24 — Свойства рассола: таблицы CRC, открытые вопросы

- **Решение:** плотность воды, растворимость и плотность рассола по таблицам CRC
  с интерполяцией; температурная поправка плотности рассола — множитель ρ_w(T)/ρ_w(20 °C).
- **Открыто:** вязкость рассола (нужна для чисел Ra, Sc на этапе 2) — выбрать корреляцию;
  влияние давления на плотность; сверить таблицы с лабораторными данными компании.
- **2026-10-24, сверка:** таблица плотности при 20 °C совпала с таблицей SANSMIC
  (Kaufman/CRC) во всех 15 точках до 4-го знака; растворимость отличается на ≤ 0,1 п.п.
  У SANSMIC есть полная таблица 0–100 °C (BSD-3) — кандидат на замену температурной
  поправки.

## 2026-10-24 — Баланс рассола: неявный перенос + перемешивание по плотности

- **Решение:** колонна слоёв по z; перенос от башмака закачки к башмаку отбора —
  неявная схема против потока; отбор Q_out = Q_in − ΔV/dt; неустойчивые по плотности
  слои мгновенно перемешиваются (изотоническая регрессия, PAV).
- **Почему:** безусловная устойчивость при крошечных начальных объёмах слоёв у скважины;
  точное сохранение соли; всплытие пресной воды при прямотоке получается само.
- **Ограничения:** первый порядок по времени; нет турбулентной диффузии между слоями
  и модели струи (часть 4 этапа 2); изменение объёма смеси при растворении не учитывается.

## 2026-10-24 — Растворение стенки: закон потока и схема Годунова

- **Решение:** поток соли j = k0·f(ψ)·C_s·u^n, u = (C_s − C)/C_s, n = 4/3; f(ψ) линеен по cos ψ
  (кровля roof_ratio = 1.5, стенка 1, подошва floor_ratio = 0). Стенка — график R(z),
  ∂R/∂t = V₀·H̃(∂R/∂z), явная схема с численным гамильтонианом Годунова.
- **Почему:** при разной скорости кровли и подошвы H̃ несимметричен и невыпуклый — выбор
  «против потока» по знаку наклона давал неверную скорость кровли (проверено тестом).
  Годунов корректен в общем случае; кровля поднимается сама, без особых правил.
- **Детали:** узел без полости (R = 0) растёт только от наклона к соседу (H̃ − 1) —
  иначе полюс сферы двигался со скоростью, заданной шагом, а не физикой. Узел берёт
  концентрацию более насыщенного из соседних слоёв: насыщенный рассол не растворяет.
- **Шаг:** КФЛ + ΔV ≤ доля·Q·dt + запрет пересыщения слоя за шаг.
- **Значения k0, n, roof_ratio** — оценка по корреляции свободной конвекции; калибровать.
- **Колонна рассола** — только ниже нерастворителя; узел на уровне нерастворителя не
  растворяется, поэтому верхний слой камеры — конус высотой Δz (артефакт порядка Δz).

## 2026-10-24 — Нерастворимые: насыпь снизу, погребение слоёв целиком

- **Решение:** твёрдая доля f_ins растворённой породы мгновенно оседает насыпью объёмом
  B·f_ins·ΔV, заполняя камеру снизу. Слой выходит из колонны рассола, когда насыпь выше
  его середины: доля 1/B его рассола вытесняется к отбору, остальное остаётся в порах.
  Узлы стенки ниже верха погребённых слоёв не растворяются.
- **Почему:** точный баланс соли без переноса рассола между слоями при каждом шаге;
  объёмы слоёв колонны только растут, поэтому неявная схема переноса не меняется.
- **Ограничения:** уровень подошвы в колонне — с точностью до слоя (Δz); оседание
  мгновенное и в центр (без конуса осыпи и без зависимости от места растворения);
  твёрдое в частично засыпанном слое до его погребения считается рассолом.
- **Башмак в насыпи** переносится на первый слой над ней — так на промысле поднимают
  колонну; число таких шагов пишется в историю, чтобы режим можно было поправить.

## 2026-10-24 — Струя и плюм от башмака (фонтан МТТ)

- **Решение:** пресная вода выходит из колонны вниз, тормозится плавучестью,
  разворачивается и всплывает плюмом с вовлечением рассола (Мортон–Тейлор–Тёрнер,
  top-hat, α = 0,09 как в SANSMIC) до уровня нейтральной плавучести. Перенос —
  неявная консервативная схема: вовлечение — сток из слоёв, смесь — источник в слое
  отдачи, между слоями — обратное течение, закрывающее объёмный баланс.
- **Почему:** мгновенное перемешивание со всеми лёгкими слоями выше (прежняя модель)
  завышало перемешивание; плюм даёт уровень отдачи и стратификацию «filling box».
- **Детали:** интегрируется M², а не M (у M особенность в точке разворота); вовлечение
  прекращается, когда радиус плюма достигает радиуса камеры; плотность внутри плюма —
  квадратичная аппроксимация таблицы (ошибка в перепаде ≈ 0,25 %).
- **Проверено:** вовлечение совпадает с теорией чистого плюма (Q ~ z^(5/3)) в пределах
  30 %; без вовлечения схема совпадает с прежним переносом; соль сохраняется точно.
- **Шаг:** соль, растворённая за шаг, должна помещаться в рассол, бывший в слое до
  шага (V_old), — прирост объёма заполняется рассолом соседей.

## 2026-10-24 — k0 по умолчанию по бенчмарку SANSMIC

- **Решение:** k0 = 3·10⁻⁵ м/с (n = 4/3). На бенчмарке прямотока объём камеры совпадает
  с SANSMIC 1.0.7 в пределах 1 %, средний радиус — 1 %.
- **Почему:** закон растворения SANSMIC откалиброван многолетними сонарными съёмками
  камер SPR; это лучшее априорное значение до данных компании. Оценка по корреляции
  свободной конвекции (1,5·10⁻⁵) того же порядка.
- **Оговорка:** SPR — купольная соль; калибровать по физической модели и данным компании.

## 2026-10-24 — SANSMIC только в единицах ft/in/bbl

- **Решение:** эталон SANSMIC считается в родных единицах и переводится в СИ.
- **Почему:** в метрическом режиме sansmic 1.0.7 выдаваемый объём делится на 5,615
  (ft³ → bbl), а прирост радиуса ≈ в 3,3 раза больше возможного (баланс соли не
  сходится). Стоит сообщить разработчикам.

## 2026-10-24 — 3D: независимые секторы, свойства в узлах

- **Решение:** множитель скорости растворения и доля нерастворимых задаются в узлах
  (z, φ), как радиус; каждый сектор движется по своему уравнению Гамильтона–Якоби, связь
  между секторами — только через концентрацию слоя.
- **Почему:** рассол в слое перемешан по горизонтали (плюм и конвекция), поэтому
  азимутальная неоднородность — свойство породы, а не рассола; независимые секторы
  дешёвы и устойчивы.
- **Ограничения:** нет горизонтального теплообмена/массообмена между секторами, струя
  всегда по оси.

## 2026-10-24 — 3D-просмотр: PyVista, Python вместо Qt/C++

- **Решение:** визуализация и будущий интерфейс — на Python (PyVista; при необходимости
  PySide6 или веб-интерфейс); расчётное ядро не переписывается на C++.
- **Почему:** ядро уже проверено и быстрое; C++ дал бы месяцы работы без новых
  возможностей. C++/Numba — только для узких мест, если появятся.

## 2026-10-24 — Карнизы: консоль от min(R_над, R_под), обрушение по вылету

- **Решение:** прослой (ангидрит, глина) — узлы с нулевой скоростью растворения. Вылет
  карниза L = min(R_над, R_под) − R_прослоя (плита закреплена там, где порода с обеих
  сторон). При L ≥ L_крит = ratio × мощность (по умолчанию 3) или `critical_span_m`
  карниз в секторе обрушивается до min(R_над, R_под); обломки — в насыпь с тем же B.
- **Почему:** простой и проверяемый критерий; конкретное значение L_крит неизвестно и на
  этапе 5 становится неопределённостью.
- **Учёт рассола:** место карниза заполняет рассол того же слоя; накопленная соль
  `collapse_fill_salt` входит в баланс. Физически этот рассол приходит снизу, где
  обломки вытесняют рассол — приближение, ошибка порядка ΔV·(C_слоя − C_низа).
- **Ограничения:** нет изгиба плиты и прочности породы, обрушение мгновенное и целиком
  на мощность прослоя; прослой-кровля не обрушивается никогда.

## 2026-10-24 — Стохастика: разделимые экспоненциальные поля, план только для скаляров

- **Решение:** поля ln k и f_ins по узлам (z, φ) — гауссовы с разделимой экспоненциальной
  ковариацией; по азимуту — через хордовое расстояние (периодично, положительно
  определено). Генерация g = L_z·W·L_φᵀ, множители Холецкого — один раз на ансамбль.
  k = exp(σg − σ²/2) (среднее 1), f = clip(f̄ + σ_f·g, 0, 0,6).
- **Почему:** без новых зависимостей (gstools не нужен), точно на нашей сетке, быстро.
  Разделимость — упрощение: анизотропия по z и φ задаётся отдельными длинами.
- **План эксперимента** (MC, LHS, Соболь) — только для скалярных параметров (k0,
  кровля/стенка, критический вылет, расход, прослои); поля всегда Монте-Карло:
  квази-Монте-Карло в тысячах измерений смысла не имеет.
- **Воспроизводимость:** реализация i = (конфигурация, seed, i): строка плана и
  `SeedSequence(seed, spawn_key=(i,))`; параллельный запуск совпадает с
  последовательным бит в бит (проверено тестом).
- **Чувствительность:** ранговая корреляция Спирмена параметр → выход; индексы Соболя
  требуют N·(d+2) прогонов и отложены.

## 2026-10-24 — Просмотр по шагам: окно на PySide6 + pyvistaqt, файл результатов .npz

- **Решение:** `saltcav view` открывает окно (PySide6, 3D — pyvistaqt, графики —
  matplotlib): ползунок моментов записи, раскраска стенки по полю, разрез через ось,
  профиль насыщения, график по времени, журнал событий; экспорт GIF/MP4 и серии .pvd для
  ParaView. Окно — тонкая обвязка: данные полей (`viz/frames.py`) и 3D-сцена
  (`viz/scene.py`) не зависят от Qt и используются также в пакетном режиме без окна.
- **Файл результатов** (`io/results.py`, формат 2): `.npz` со всем, что нужно для
  просмотра, — форма, концентрации, скорость стенки, башмаки, нерастворитель, свойства
  породы, события, исходная конфигурация (YAML). Читается без saltcav; старые файлы
  `run --out` открываются (без скорости и событий).
- **Почему:** сделан до этапа 9, потому что напряжения и деформации этапа 6 нужно
  смотреть так же по шагам — их добавим в то же окно новыми полями. Qt — тот же стек,
  что и будущий интерфейс (решение «всё на Python»).
- **Ограничения:** шаги — это моменты записи (`output_every_days`, `--every`), а не
  каждый шаг расчёта: шагов сотни-тысячи, хранить их все не нужно. Частота записи
  ограничивает шаг по времени, поэтому результаты при разной `--every` отличаются
  на уровне погрешности схемы.
- **Реализация ансамбля** пересчитывается целиком: `--realization N -n … --seed …` даёт
  ту же реализацию, что в ансамбле (проверено тестом), — так смотрят «худший» случай.

## 2026-10-24 — Ввод параметров: JSON Schema для редактора сейчас, окно — после этапа 6

- **Решение:** схема конфигурации (`schema/saltcav-config.schema.json`) строится из
  pydantic-модели (`saltcav schema`); у каждого поля описание с единицами. YAML-файлы
  ссылаются на неё строкой `# $schema: …` — PyCharm и VS Code дают автодополнение,
  подсказки и проверку. Тест сверяет схему в репозитории с моделью.
- **Почему:** один источник правды — модель конфигурации; та же схема станет основой
  форм препроцессора в окне (после этапа 6, когда добавятся параметры геомеханики).

## 2026-10-24 — Геомеханика: свой осесимметричный МКЭ, 3D — позже через SafeInCave

- **Решение (пересмотр решения о FEniCSx):** первая версия геомеханики — собственный
  осесимметричный МКЭ на NumPy/SciPy (треугольники P2, B̄, линеаризованная неявная схема
  ползучести), сетка — Gmsh. Форма 3D-камеры приводится к осесимметричной по
  эквивалентному радиусу. Полный 3D — следующим шагом: экспорт сетки и расчёт в
  SafeInCave (TU Delft, BSD-3, FEniCSx 0.9) там, где важна асимметрия.
- **Почему:** FEniCSx и SafeInCave на Windows ставятся только через WSL — для работы в
  PyCharm и для ансамблей (этап 7, сотни расчётов) это тяжело. Осесимметричная задача —
  стандарт для одиночной камеры; 2 тыс. элементов, 30 лет ползучести — 5–10 с.
  Верификация на аналитике (Ламе, сфера, установившаяся ползучесть цилиндра, MMS)
  встроена в тесты, поэтому риск «своего МКЭ» контролируется.
- **B̄ обязателен:** ползучесть соли несжимаема; без B̄ треугольники P2 «запираются» —
  скорость сходимости цилиндра была 115 вместо 180 м/год (−36 %) и падала с ростом шага.
  С B̄ (объёмная деформация постоянна в элементе) совпадение 0,2 %; плата — второй
  порядок сходимости перемещений вместо третьего.
- **Закон ползучести:** BGRa (Hunsche, Hampel) + неустановившаяся Мансона–Доусона
  (параметры WIPP) — иллюстрация до испытаний керна; ветви и параметры задаются в YAML.
- **Критерии:** дилатансия по Ratigan (√J₂ = 0,27·I₁), напряжения вдоль стенки против
  давления в камере (SMRI), конвергенция. Критерий DeVries/Spiers — по данным.
- **Ограничения:** форма камеры не меняется во время выщелачивания (механика по
  итоговой форме, связь односторонняя); соль однородна (прослои в механике пока как
  соль); K₀ = 1; малые деформации. Запас по дилатансии у острых углов карнизов
  чувствителен к сетке (±5 % при h = 2…0,5 м), конвергенция — нет (0,1 %).

## 2026-10-24 — Окно программы: формы строятся из модели конфигурации

- **Решение:** препроцессор (`saltcav gui`) не описывает параметры вручную: формы
  строятся по pydantic-модели `RunConfig` — тип поля задаёт редактор, описание —
  подпись, ограничения и умолчания — подсказку; списки моделей — таблицы. Проверяет
  сама модель, ошибки по пути поля подсвечиваются в форме, сообщения переведены.
- **Почему:** один источник правды для YAML, `saltcav check`, подсказок PyCharm и окна;
  новый параметр (например, геомеханики) появляется в окне без правки интерфейса.
- **Файлы:** окно пишет только явно заданные значения; пустое поле — умолчание модели.
  Комментарии исходного YAML при сохранении из окна не сохраняются.
- **Расчёты** — в отдельном потоке с индикатором и отменой; ансамбль — на всех ядрах.

## 2026-10-24 — Симметрия — следствие параметров; предупреждения о несогласованности

- **Решение:** отдельного «режима» осесимметрия/3D нет: число секторов и источники
  асимметрии (k_variation, поле ln k) задаются независимо. Несогласованные сочетания
  выдают предупреждения (`config_warnings`: `saltcav check`, окно), расчёт не блокируют.
- **Исправлено:** при одном секторе `k_variation` превращался в общий множитель скорости
  (cos(180° − φ₀) единственного сектора) — теперь при nphi = 1 азимутальная вариация не
  применяется. Примеры и тесты это не затрагивало (там k_variation = 0 при nphi = 1).

## 2026-10-24 — 3D-геомеханика: свой МКЭ на тетраэдрах P2, PARDISO, PCG со старым разложением

- **Решение:** `mechanics.model: 3d` — полная форма R(z, φ). Полость — кольца-сплайны по
  глубине (площадь сечения как в модели выщелачивания), соседние кольца — линейчатые
  поверхности (OpenCASCADE), массив — цилиндр минус полость, тетраэдры P2 с прямыми
  рёбрами. Тот же закон ползучести, та же неявная схема и B̄; решатель ползучести общий
  для осесимметрии и 3D. Разложение — PARDISO (`pypardiso`, Intel MKL); касательная
  матрица меняется медленно, поэтому старое разложение — предобусловливатель для CG,
  пересчёт — когда итераций больше 12.
- **Почему не SafeInCave:** на Windows — только WSL; свой решатель работает в том же
  venv, что и окно, и в ансамблях. SafeInCave остаётся кандидатом для независимой сверки.
- **Проверено:** сфера — 0,5 % (u) при h = 2 м; симметричная камера — 3D и осесимметрия
  совпадают: конвергенция в пределах 2 %, запас по дилатансии — 4 %.
- **Найдено при проверке:** объём полости по деформированной границе надо считать с
  пересчётом нормалей; при неподвижной нормали изменение объёма занижается втрое.
- **Цена:** ~10–20 тыс. тетраэдров, 100–170 тыс. неизвестных; 2 года ползучести — ~45 с,
  15 лет с неустановившейся ползучестью — минуты (2 ядра); память — 2–3 ГБ.
  Без PARDISO (SuperLU) — в десятки раз медленнее.
