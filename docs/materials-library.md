# Библиотека пород и рабочих сред

Формат, загрузчик, привязка пород к слоям, локальные переопределения свойств, выбор
среды закачки и выборка из библиотечных диапазонов для этапа 1.x-а (версия 1.2).
Локально переопределять можно только свойства, которые уже передаются в расчёт;
произвольные распределения ансамбля и редактор локальных переопределений в окне пока
не реализованы.

Записи `test-synthetic-rock` и `test-synthetic-fluid` — синтетические тестовые фикстуры
с произвольными значениями, а не инженерные данные. Они нужны для самопроверки и тестов.
Запись `nacl-saturated-20c-nist` — отдельная справочная точка насыщенного рассола при 20 °C
из [IUPAC/NIST, таблица 9](https://srdata.nist.gov/solubility/IUPAC/SDS-47/SDS-47.pdf):
плотность 1200,4 кг/м³ и доля соли 0,2640 дают концентрацию 316,9056 кг/м³.
Равные границы диапазона обозначают эту точку, а не неопределённость или интервал температур.
В расчёт при выборе среды передаётся только концентрация; плотность и температура записи
не заменяют таблицы и температуру модели 1.x. Совпадение таблиц 1.x с NIST не предполагается.
Запись `water-default-1x` хранит нулевую концентрацию закачки по умолчанию 1.2;
её источник — конфигурация SaltCav, а не таблица физических свойств.
Запись `jintan-fusi-layer-1` содержит плотность по каротажу конкретного пласта
794,8–809,0 м из [Cen и др., таблица 3](https://doi.org/10.3390/pr12061124):
2,06 г/см³ пересчитаны в 2060 кг/м³. Равные границы не характеризуют погрешность;
эта плотность не подставляется в геологию или геомеханику при выборе материала слоя.
Запись `salt-default-1x` содержит прежние умолчания общей соли: плотность, модуль Юнга,
коэффициент Пуассона и параметры ползучести. Их источник — конфигурация SaltCav 1.2,
а не измерения керна.

Общую соль можно явно применить через Python API:

```python
import saltcav.api as sc

cfg = sc.load("configs/example.yaml")
cfg = sc.apply_bulk_salt(cfg, "data/materials_library", "salt-default-1x")
```

Функция возвращает новую конфигурацию и заменяет указанные в записи плотность общей соли,
модуль Юнга и коэффициент Пуассона, даже если они были заданы явно; отсутствующие свойства
остаются прежними. При сохранении конфигурации записываются применённые числа, а не ссылка
на библиотеку. Полные наборы `creep_*` и `transient_*` заменяют соответственно ветви
ползучести и параметры Мансона–Доусона; неполный набор вызывает ошибку. Отсутствующий
набор сохраняет прежнее значение. Таблицы рассола функция не подключает.

## Расположение и запись

Корень библиотеки содержит каталоги `materials/` для пород и `fluids/` для рабочих сред.
Одна запись — один файл `.yaml` или `.yml` непосредственно в соответствующем каталоге.
Один из каталогов может отсутствовать. Имена файлов произвольны; связь с записью задаёт
её стабильный `id`, уникальный среди обоих каталогов.

```yaml
id: test-synthetic-fluid
name: Synthetic fluid — loader test fixture only
kind: synthetic_fluid
properties:
  density:
    quantity: density
    value: 1000.0
    unit: kg/m3
    range: [500.0, 1500.0]
    source:
      reference: Synthetic fixture for SC-004 loader tests; not a physical source
      location: Not applicable — arbitrary test value
```

Поля записи:

| Поле | Содержание |
| --- | --- |
| `id` | Стабильный идентификатор: строчные латинские буквы, цифры, `-` и `_`; первый символ — буква или цифра. После публикации записи идентификатор не меняют и не используют повторно для другой записи. |
| `name` | Непустое название для отображения; можно менять без изменения `id`. |
| `kind` | Непустой вид породы или среды, например `halite` или `nacl_brine`. Это классификация записи, а не её идентификатор. |
| `properties` | Непустое отображение числовых свойств. Ключ — строчное имя в `snake_case`. |

Каждое числовое свойство имеет вид:

| Поле | Содержание |
| --- | --- |
| `quantity` | Идентификатор физической величины из таблицы ниже. |
| `value` | Конечное целое или дробное числовое значение в указанной единице СИ; `true` и `false` не допускаются. |
| `unit` | Каноническое написание единицы СИ для `quantity`. |
| `range` | Ровно две конечные числовые границы `[minimum, maximum]` в той же единице; логические значения запрещены. `minimum <= value <= maximum`; границы включаются, равные границы допускаются. |
| `source.reference` | Непустое полное обозначение источника: авторы или организация, название, издание/год, DOI/URL или иной проверяемый идентификатор, если есть. |
| `source.location` | Точное место: страница, таблица, уравнение, раздел или строка набора данных. Обязательно, если у источника есть такое место. Для синтетики явно пишут, что место неприменимо. |

Источник задаётся отдельно для каждого свойства: значения одной записи могут происходить
из разных работ. Пустые строки и строки из одних пробелов не считаются источником.
Неизвестные поля и повторяющиеся ключи в любом YAML-отображении запрещены: загрузчик
отклоняет файл, а не использует молча последнее значение. Все значения и границы — только
в СИ; `MPa`, `g/l`, `cP`, °C и другие промысловые или внесистемные единицы в файле
библиотеки не допускаются.
Загрузчик ничего не пересчитывает: перевод в СИ выполняет автор записи на границе ввода,
с проверкой по первоисточнику.

## Физические величины и единицы

Соответствие проверяется по `saltcav.materials.QUANTITY_UNITS`. Сейчас поддержаны:

| `quantity` | Единица СИ (`unit`) |
| --- | --- |
| `activation_energy` | `J/mol` |
| `compressibility` | `1/Pa` |
| `density`, `mass_concentration` | `kg/m3` |
| `diffusivity`, `kinematic_viscosity` | `m2/s` |
| `dimensionless` | `"1"` |
| `dynamic_viscosity` | `Pa*s` |
| `length` | `m` |
| `mass` | `kg` |
| `pressure`, `stress` | `Pa` |
| `specific_heat_capacity` | `J/(kg*K)` |
| `strain_rate` | `1/s` |
| `temperature` | `K` |
| `thermal_conductivity` | `W/(m*K)` |
| `thermal_expansion` | `1/K` |
| `time` | `s` |
| `velocity` | `m/s` |

Это реестр размерностей, а не перечень обязательных свойств. Например, свойство
`youngs_modulus` имеет `quantity: stress` и `unit: Pa`. Если нужной физической величины
нет, её и каноническую единицу добавляют в `QUANTITY_UNITS` вместе с тестом; неверную или
незнакомую единицу нельзя обходить переименованием `quantity`.

## Загрузка

```python
from saltcav.materials import load_library

library = load_library("data/materials_library")  # далее — синтетические записи
rock = library.materials["test-synthetic-rock"]
fluid = library.fluids["test-synthetic-fluid"]

print(rock.properties["density"].value)  # число в СИ
print(fluid.properties["density"].range)  # границы в той же единице СИ
print(fluid.properties["density"].source.reference)
```

Для своей библиотеки вместо пути к фикстурам передают её корень. YAML читается через
наследника `yaml.SafeLoader`, поэтому произвольные YAML-теги не создают объекты Python и не
выполняют код. Дополнительная проверка отклоняет повторяющиеся ключи на любом уровне.
Любая ошибка схемы или YAML вызывает `LibraryValidationError`; сообщение содержит файл и
путь поля, например `materials/rock.yaml: properties.density.unit: ...`. При повторе
ключа указывается этот ключ, а при повторе `id` дополнительно указывается файл первой записи.

## Привязка породы к геологическому слою

Ссылка задаётся стабильным `id`, а корень библиотеки — отдельным верхнеуровневым полем:

```yaml
# SYNTHETIC TEST FIXTURE ONLY: произвольные значения, не физический справочник.
materials_library: ../library  # относительно каталога этого YAML, не текущего каталога команды
geology:
  layers:
    - kind: anhydrite
      material_id: test-sc006-synthetic-anhydrite
      top_m: 1040.0
      thickness_m: 1.0
      material_overrides:
        critical_span: 7.0  # м; только для этого слоя
      # critical_span_m: 8.0  # если задано, имеет приоритет над override
```

`load_config` загружает библиотеку один раз, если есть хотя бы одна ссылка на породу или
среду, и разрешает все ссылки до расчёта. Этот же путь используют `saltcav check`,
`saltcav run` и Python API. В загруженной конфигурации `materials_library` становится
абсолютным путём. Конфигурации без `material_id` и `injection_fluid_id` не обращаются к
библиотеке и не требуют её наличия.

`kind` слоя должен точно совпадать с `kind` записи. Нельзя ссылаться на запись из `fluids/`;
неизвестный `id` не заменяется материалом по умолчанию. Отсутствие `materials_library` при
наличии ссылки, отсутствие каталога, неизвестный или неподходящий `id`, конфликт `kind` и
несовместимое применяемое свойство — ошибки с именем YAML, индексом слоя и полем.

### Поддерживаемое соответствие свойств

| Свойство записи | Обязательные `quantity` и `unit` | Поле слоя | Существующий расчётный смысл |
| --- | --- | --- | --- |
| `critical_span` | `length`, `m` | `critical_span_m` | Критический вылет в критерии обрушения карниза (`leaching/ledges.py`) |

Это исчерпывающая таблица применяемых свойств, а не сопоставление по совпадающим именам.
Например, `density` и `youngs_modulus` остаются справочными: они не меняют общую
`geology.salt_density_kg_m3` или записи `mechanics.layer_materials`. Для них нет автоматической
послойной подстановки и скрытых преобразований. Остальные свойства записи также сохраняются
только как данные библиотеки; послойное переопределение и выборка ансамбля для них не поддерживаются.

### Локальное переопределение свойства

Поле `material_overrides` задаёт значения только для одного слоя с `material_id`:

```yaml
material_overrides:
  critical_span: 7.0
```

Ключом является имя свойства из таблицы выше (`critical_span`), а не имя поля слоя
(`critical_span_m`). Сейчас другие ключи, включая справочные `density` и `youngs_modulus`,
отклоняются. Само переопределение требует `material_id`; без ссылки на материал оно является
ошибкой, а не самостоятельным способом задать поле слоя.

Значение — одно конечное число в канонической единице СИ из таблицы, без вложенных `quantity`,
`unit`, `range` и `source`. Для `critical_span` это метры: `critical_span: 7.0` эквивалентно
`critical_span_m: 7.0`. Пересчёта единиц нет. Значение проходит ту же проверку `LayerConfig`,
что и библиотечное: для критического вылета требуется `> 0`; `null`, логические и нечисловые
значения запрещены. Неизвестное свойство и недопустимое значение отклоняются при `load_config`
до расчёта; путь ошибки содержит индекс слоя и свойство, например
`geology.layers.0.material_overrides.critical_span`.

Переопределение не меняет запись библиотеки и другие слои, ссылающиеся на тот же `material_id`.
Неуказанные поддерживаемые свойства по-прежнему наследуются независимо. Для переопределённого
значения `material_sources` не заполняется: источник из записи относится только к
библиотечному значению, которое в этом слое не применяется.

### Порядок выбора значения

Для каждого поддерживаемого свойства действует порядок:

1. явно заданное в YAML поле слоя, отличное от `null` (например, `critical_span_m`);
2. `material_overrides[имя_свойства]`, если поле слоя отсутствует или равно `null`;
3. значение свойства из записи библиотеки;
4. прежнее умолчание модели, если значения нет ни в override, ни в записи (для
   `critical_span_m` это `null`, то есть `ledge_span_ratio × thickness_m`).

Загрузчик различает отсутствующее поле и автоматически подставленный pydantic-default через
набор явно заданных полей. Явный `null` в поле слоя означает отсутствие значения и позволяет
применить override или библиотеку. У библиотечного значения `quantity` и `unit` дополнительно
сверяются с таблицей. Источник каждого фактически применённого библиотечного значения
сохраняется в `layer.material_sources[имя_поля]`; источник явного значения слоя или локального
override библиотекой не заменяется.

### Выборка свойства из диапазона в ансамбле

Список `ensemble.layer_properties` явно задаёт, какое свойство какого слоя варьировать. Индекс
слоя отсчитывается с нуля в `geology.layers`, а имя свойства совпадает с ключом записи
библиотеки и с ключом `material_overrides` из формата локальных переопределений:

Ниже `<...>` обозначает данные существующей конфигурации и библиотеки. Это схематичный
фрагмент, а не новая библиотечная запись или источник числовых значений:

```yaml
materials_library: <корень_существующей_библиотеки>
geology:
  layers:
    - kind: <kind_записи>
      material_id: <id_записи>
      # Остальные поля слоя — как в основной конфигурации.
      # critical_span_m и material_overrides.critical_span здесь не задают.
ensemble:
  # n_realizations, seed и sampler наследуются из основной конфигурации.
  layer_properties:
    - layer: <индекс_слоя>
      property: critical_span
```

Для каждого правила к существующему плану эксперимента ансамбля добавляется один столбец.
Если `u` — число из этого столбца для данной реализации, а библиотечный диапазон равен
`[x_min, x_max]`, значение вычисляется по равномерному закону:

```text
x = x_min + (x_max − x_min) × u
```

Значение и обе границы выражены в одной единице СИ, пересчёта единиц нет. Равные границы дают
постоянное значение. Способ покрытия единичного интервала по-прежнему определяется
`ensemble.sampler`: `mc`, `lhs` или `sobol`; отдельный генератор случайных чисел для свойств
материала не создаётся. Поэтому тот же `ensemble.seed`, число реализаций и номер реализации дают
то же значение независимо от числа процессов. Правила применяются в порядке списка, а выбранные
значения сохраняются в `EnsembleResult.params` под именами вида `layer0_critical_span`.

Выборка заменяет только указанное поле только указанного слоя в копии конфигурации реализации.
Другие слои, в том числе ссылающиеся на тот же `material_id`, сохраняют свои значения. Исходная
конфигурация и запись библиотеки не изменяются; `material_sources` продолжает указывать источник
свойства и диапазона. В одиночном расчёте без номера реализации эти правила не применяются.

До запуска расчёта правило отклоняется, если:

- индекс слоя неверен, у слоя нет `material_id` либо свойство не входит в таблицу поддерживаемых;
- в записи нет выбранного свойства или его `range`;
- то же поле задано явно (`critical_span_m` для `critical_span`) или через
  `material_overrides.critical_span`; явный `null` переопределением не считается;
- для той же пары «слой, свойство» уже есть правило в `layer_properties`;
- для `critical_span` задан ненулевой `uncertainty.ledge_span_log_sd`, который уже варьирует
  критический вылет карниза.

Сообщение ошибки содержит индекс слоя и имя свойства. Пустой по умолчанию список
`layer_properties` не добавляет столбцов в план: прежние конфигурации, одиночный расчёт и
ансамбль с фиксированным seed сохраняют прежние результаты.

## Выбор рабочей среды закачки

Среда закачки задаётся необязательной ссылкой в разделе `leaching`; корень библиотеки общий
с привязкой пород:

```yaml
# SYNTHETIC TEST FIXTURE ONLY: произвольные значения, не физический справочник.
materials_library: ../library  # относительно каталога этого YAML
leaching:
  injection_fluid_id: test-synthetic-fluid
  # injection_concentration_kg_m3: 100.0  # явное значение имеет приоритет
```

Ссылка должна указывать на запись из `fluids/`. Неизвестный идентификатор и идентификатор
записи из `materials/` отклоняются при `load_config`, до запуска расчёта; ошибка содержит
`leaching.injection_fluid_id` и указанный `id`.

| Свойство записи | Обязательные `quantity` и `unit` | Поле конфигурации | Существующий расчётный смысл |
| --- | --- | --- | --- |
| `mass_concentration` | `mass_concentration`, `kg/m3` | `leaching.injection_concentration_kg_m3` | Массовая концентрация NaCl в закачиваемой среде; передаётся в существующий вход `c_in` переноса и плюма |

Значение используется в кг/м³ без преобразований внутри расчёта. При одновременном задании
ссылки и `injection_concentration_kg_m3` приоритет имеет явно заданное значение, включая
`0.0`. Если поле отсутствует, применяется `mass_concentration` выбранной среды; если у записи
нет этого свойства либо ссылка не задана, сохраняется прежнее значение модели `0.0` кг/м³
(пресная вода). Другие свойства среды автоматически не подставляются. Ссылка не меняет
начальное насыщение камеры, нерастворитель и параметры геомеханики.

## Температурные таблицы рассола

Записи `nacl-default-1x` и `nacl-reference-tables` содержат ряды числовых свойств в СИ.
Суффикс имени свойства задаёт температуру в °C; в `brine_density_20_*` суффикс —
массовый процент NaCl при 20 °C. Эти записи имеют вид `nacl_brine_tables` и не
являются средами закачки.

`LegacyBrineTables(load_library(root))` воспроизводит табличные функции плотности воды,
растворимости и плотности рассола 1.x. `BrineReference(load_library(root))` позволяет
получить массовую долю насыщения и плотность насыщенного рассола из IUPAC/NIST SDS-47,
а также `viscosity_molal(m, T)` для 0–6 моль NaCl на кг воды из таблиц 1–13 Kestin и др.
(NIST). Суффикс `viscosity_m_N_t_T`: N — число полу-моль/кг, T — температура °C.
При давлении p* = максимум из 0,1 МПа и давления насыщенных паров воды используются
линейная интерполяция по температуре и моляльности, без экстраполяции. Две точки
(4 моль/кг при 30 °C и 5,5 моль/кг при 80 °C) исключены из-за расхождений между
копиями NIST; по температуре интерполируются соседние точки. Методы принимают °C и
отклоняют значения за границами: 0–100 °C для 1.x, 20–100 °C для NIST. Для насыщенного
раствора моляльность превышает 6 моль/кг, поэтому эти таблицы не покрывают насыщение.
Вычислительные функции 1.x автоматически читают свои табличные значения, коэффициенты
вязкости воды и диффузии из поставляемой библиотеки; формулы не меняются. Плотность,
упругость и параметры ползучести общей соли, а также концентрация закачки по умолчанию
читаются из записей 1.x; явно заданные значения конфигурации имеют приоритет.
`nacl-saturated-20c-nist` содержит оценку вязкости насыщенного рассола при 20 °C:
2,0238 мПа·с получены линейной экстраполяцией таблицы CRC 84-го издания от 24 и 26%
до концентрации насыщения 26,40% из SDS-47. Это оценка вне таблицы CRC, а не
измеренное справочное значение; точечный `range` не является неопределённостью.
Оценка погрешности округления исходных точек и концентрации — не более 0,0012 мПа·с;
погрешности модели и измерений неизвестны и в эту оценку не входят.
Температурный ряд вязкости насыщенного раствора эта оценка не задаёт.
Источник старых чисел —
код 1.x: сверка именно с CRC ещё не выполнена.

## Как добавить запись

1. Проверьте значение и диапазон по первоисточнику. Не добавляйте неподтверждённые числа
   и не придумывайте источник или место в нём.
2. Создайте один YAML-файл в `materials/` или `fluids/`. Выберите постоянный `id`, задайте
   `name` и `kind`; для каждого свойства заполните все обязательные поля из таблиц выше.
3. Переведите значение и обе границы в СИ и укажите каноническую `unit`. Для каждого
   свойства запишите проверяемый `source.reference` и точный `source.location`, если он
   применим.
4. Загрузите корень через `load_library()` и исправьте все ошибки. Для нового `quantity`
   сначала расширьте реестр единиц и добавьте тест на несоответствие единицы.

Тестовые фикстуры не являются физическим справочником и не задают значения по умолчанию
для существующих моделей.
