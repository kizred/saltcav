# Библиотека пород и рабочих сред

Формат и загрузчик для этапа 1.x-а (версия 1.2). Сейчас реализованы только хранение и
проверка записей: привязки к слоям, переопределения свойств, распределения ансамбля,
пользовательские каталоги и выбор в окне не входят в этот этап. Загрузчик не меняет
конфигурацию и не подставляет значения в расчёты.

В репозитории нет физического справочника. Две записи в
`tests/fixtures/materials_library/` — **синтетические тестовые фикстуры с произвольными
значениями**, а не справочные данные; использовать их в расчётах нельзя.

## Расположение и запись

Корень библиотеки содержит каталоги `materials/` для пород и `fluids/` для рабочих сред.
Одна запись — один файл `.yaml` или `.yml` непосредственно в соответствующем каталоге.
Один из каталогов может отсутствовать. Имена файлов произвольны; связь с записью задаёт
её стабильный `id`, уникальный среди обоих каталогов.

```yaml
id: test-synthetic-fluid
name: Synthetic fluid — loader test fixture only
kind: synthetic_fluid
properties:
  density:
    quantity: density
    value: 1000.0
    unit: kg/m3
    range: [500.0, 1500.0]
    source:
      reference: Synthetic fixture for SC-004 loader tests; not a physical source
      location: Not applicable — arbitrary test value
```

Поля записи:

| Поле | Содержание |
| --- | --- |
| `id` | Стабильный идентификатор: строчные латинские буквы, цифры, `-` и `_`; первый символ — буква или цифра. После публикации записи идентификатор не меняют и не используют повторно для другой записи. |
| `name` | Непустое название для отображения; можно менять без изменения `id`. |
| `kind` | Непустой вид породы или среды, например `halite` или `nacl_brine`. Это классификация записи, а не её идентификатор. |
| `properties` | Непустое отображение числовых свойств. Ключ — строчное имя в `snake_case`. |

Каждое числовое свойство имеет вид:

| Поле | Содержание |
| --- | --- |
| `quantity` | Идентификатор физической величины из таблицы ниже. |
| `value` | Конечное числовое значение в указанной единице СИ. |
| `unit` | Каноническое написание единицы СИ для `quantity`. |
| `range` | Ровно две конечные границы `[minimum, maximum]` в той же единице; `minimum <= value <= maximum`. Границы включаются, равные границы допускаются. |
| `source.reference` | Непустое полное обозначение источника: авторы или организация, название, издание/год, DOI/URL или иной проверяемый идентификатор, если есть. |
| `source.location` | Точное место: страница, таблица, уравнение, раздел или строка набора данных. Обязательно, если у источника есть такое место. Для синтетики явно пишут, что место неприменимо. |

Источник задаётся отдельно для каждого свойства: значения одной записи могут происходить
из разных работ. Пустые строки и строки из одних пробелов не считаются источником.
Неизвестные поля запрещены. Все значения и границы — только в СИ; `MPa`, `g/l`, `cP`,
°C и другие промысловые или внесистемные единицы в файле библиотеки не допускаются.
Загрузчик ничего не пересчитывает: перевод в СИ выполняет автор записи на границе ввода,
с проверкой по первоисточнику.

## Физические величины и единицы

Соответствие проверяется по `saltcav.materials.QUANTITY_UNITS`. Сейчас поддержаны:

| `quantity` | Единица СИ (`unit`) |
| --- | --- |
| `activation_energy` | `J/mol` |
| `compressibility` | `1/Pa` |
| `density`, `mass_concentration` | `kg/m3` |
| `diffusivity`, `kinematic_viscosity` | `m2/s` |
| `dimensionless` | `"1"` |
| `dynamic_viscosity` | `Pa*s` |
| `length` | `m` |
| `mass` | `kg` |
| `pressure`, `stress` | `Pa` |
| `specific_heat_capacity` | `J/(kg*K)` |
| `strain_rate` | `1/s` |
| `temperature` | `K` |
| `thermal_conductivity` | `W/(m*K)` |
| `thermal_expansion` | `1/K` |
| `time` | `s` |
| `velocity` | `m/s` |

Это реестр размерностей, а не перечень обязательных свойств. Например, свойство
`youngs_modulus` имеет `quantity: stress` и `unit: Pa`. Если нужной физической величины
нет, её и каноническую единицу добавляют в `QUANTITY_UNITS` вместе с тестом; неверную или
незнакомую единицу нельзя обходить переименованием `quantity`.

## Загрузка

```python
from saltcav.materials import load_library

library = load_library("tests/fixtures/materials_library")  # только синтетический пример
rock = library.materials["test-synthetic-rock"]
fluid = library.fluids["test-synthetic-fluid"]

print(rock.properties["density"].value)  # число в СИ
print(fluid.properties["density"].range)  # границы в той же единице СИ
print(fluid.properties["density"].source.reference)
```

Для своей библиотеки вместо пути к фикстурам передают её корень. YAML читается через
`yaml.safe_load`. Любая ошибка схемы или YAML вызывает `LibraryValidationError`; сообщение
содержит файл и путь поля, например
`materials/rock.yaml: properties.density.unit: ...`. При повторе `id` дополнительно
указывается файл первой записи.

## Как добавить запись

1. Проверьте значение и диапазон по первоисточнику. Не добавляйте неподтверждённые числа
   и не придумывайте источник или место в нём.
2. Создайте один YAML-файл в `materials/` или `fluids/`. Выберите постоянный `id`, задайте
   `name` и `kind`; для каждого свойства заполните все обязательные поля из таблиц выше.
3. Переведите значение и обе границы в СИ и укажите каноническую `unit`. Для каждого
   свойства запишите проверяемый `source.reference` и точный `source.location`, если он
   применим.
4. Загрузите корень через `load_library()` и исправьте все ошибки. Для нового `quantity`
   сначала расширьте реестр единиц и добавьте тест на несоответствие единицы.

Записи с физическими справочными данными появятся отдельно; тестовые фикстуры не являются
таким справочником и не задают значения по умолчанию для существующих моделей.
