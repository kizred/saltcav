# Формат данных скважины

Данные одной скважины — папка с CSV-файлами (обязателен хотя бы один). Так их удобно
выгружать из Excel и проверять глазами; программа читает папку целиком:

```bash
saltcav data data/demo/well-1 --config configs/demo_calibration.yaml   # проверить
saltcav calibrate configs/demo_calibration.yaml --data data/demo/well-1  # калибровать
```

В окне — вкладка «Калибровка» → «Данные…».

## Как читаются файлы

- Разделитель «,» или «;» — определяется сам; при «;» допускается десятичная запятая
  (выгрузка из русского Excel: «Сохранить как → CSV (разделители — точки с запятой)»).
- Кодировка UTF-8 (с BOM или без) или Windows-1251.
- Первая строка — имена столбцов (регистр не важен), порядок столбцов — любой, лишние
  столбцы (комментарии, номера) игнорируются; пустые строки пропускаются.
- Время — **сутки от начала выщелачивания** (дробные допустимы); глубины — **м от
  поверхности, вниз**; азимут — **° по часовой от направления φ = 0** модели (то же, что
  `geology.k_variation_azimuth_deg`).

Проверка (`saltcav data`, окно) не исправляет данные, а перечисляет замечания: разрывы и
перекрытия ступеней режима, немонотонное время замеров, концентрация выше насыщения
(чаще всего — не те единицы), замеры после конца режима, сонар вне сетки модели.

## operations.csv — журнал режима

Ступени режима подряд, без разрывов.

| столбец | единицы | смысл |
| --- | --- | --- |
| `day_start`, `day_end` | сут | начало и конец ступени |
| `mode` | — | `direct` — прямоток (вода в центральную колонну), `reverse` — противоток |
| `rate_m3_per_h` | м³/ч | средний расход закачки пресной воды на ступени |
| `injection_depth_m` | м | башмак колонны закачки |
| `production_depth_m` | м | башмак колонны отбора |
| `blanket_depth_m` | м | уровень нерастворителя |

Если в журнале расход меняется чаще, чем меняются колонны, — разбейте на ступени по
изменениям расхода (сутки или недели) или усредните. При калибровке режим из файла
заменяет раздел `schedule` конфигурации.

## brine.csv — рассол на выходе

| столбец | единицы | смысл |
| --- | --- | --- |
| `day` | сут | момент замера |
| `concentration_kg_m3` | кг/м³ | концентрация NaCl, **или** |
| `density_kg_m3` | кг/м³ | плотность рассола — пересчитывается в концентрацию по таблице при температуре из `well.yaml` (по умолчанию 20 °C) |
| `sigma_kg_m3` | кг/м³ | по желанию: погрешность замера; без столбца — `calibration.sigma_concentration_kg_m3` |

Пример (Excel, «;»):

```
day;concentration_kg_m3;sigma_kg_m3
5;53,70;4,00
10;76,24;4,00
```

## sonar.csv — сонарные съёмки

Одна строка — одна точка стенки. Съёмки различаются по `day`.

| столбец | единицы | смысл |
| --- | --- | --- |
| `day` | сут | момент съёмки |
| `depth_m` | м | глубина точки |
| `azimuth_deg` | ° | азимут; пусто — съёмка без азимута (эквивалентный радиус) |
| `radius_m` | м | расстояние от оси скважины до стенки |

С азимутами точка сравнивается с радиусом модели в том же секторе; без азимутов — с
эквивалентным радиусом √(среднее R²) на этой глубине. Точки, где камера уже ствола
(сонар не видит стенку), лучше не выгружать.

## layers.csv — прослои (по желанию)

| столбец | единицы | смысл |
| --- | --- | --- |
| `kind` | — | `anhydrite`, `clay` (не растворяются) или `halite` |
| `top_m` | м | кровля прослоя |
| `thickness_m` | м | мощность |

По ГИС скважины; при калибровке заменяют прослои из конфигурации (неопределённость
отметок для ансамбля задаётся в конфигурации).

## well.yaml — описание (по желанию)

```yaml
name: Скв. 1
temperature_c: 30        # температура рассола: насыщение и пересчёт плотности
notes: откуда данные, какие замеры исключены и почему
```

## Наборы в репозитории

| папка | что это |
| --- | --- |
| `data/demo/well-1` | синтетика «как от компании»: модель со скрытыми параметрами (`truth.yaml`) + шум замеров (рассол 4 кг/м³, сонар 0,4 м); 240 сут, прямоток → противоток, 12 секторов, сонар на 60, 150 и 240 сут по 8 азимутам; CSV в стиле Excel. Конфигурация — `configs/demo_calibration.yaml` |
| `data/open/sansmic-direct` | открытый эталон: расчёт SANSMIC (Sandia) — плотность на выходе каждые 2 сут и профили R(z) на 25, 50, 75, 100 сут. Конфигурация — `configs/benchmark_sansmic_direct.yaml` |

Свои синтетические наборы: `saltcav synth CONFIG --out ПАПКА --truth k0=2e-5 --truth
roof_ratio=1.8 --sonar-days 60,150,240 --sigma-c 4 --sigma-r 0.4 [--excel]`.
Данные компании в git не попадают (`data/*` в `.gitignore`, кроме `demo` и `open`).
